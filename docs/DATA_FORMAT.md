# 데이터 형식

## 목적

이 문서는 텍스트 가져오기와 로컬 저장 형식이 지켜야 할 경계를 정의한다. 현재는 TXT 가져오기
및 메모리 내 콘텐츠 모델을 제공하며 SQLite 스키마는 아직 구현하지 않았다.

## 콘텐츠 계층

콘텐츠의 논리 구조는 다음과 같다.

```text
Book
└── Chapter
    └── Paragraph
        └── Sentence
```

`Book`, `Chapter`, `Paragraph`, `Sentence`는 목록 위치와 무관한 문자열 ID를 가진다. 하위
엔터티는 부모 ID와 0부터 시작하는 `source_order`를 저장한다. 자식 목록은 원문 순서대로 정렬된
불변 튜플이다. 문장에는 정본인 `original_text`를 저장한다. 이벤트용 `display_text`나 사용자의
`typed_text`로 이를 덮어쓰지 않는다.

`Book.original_text`는 가져온 파일 전체를 그대로 보존한다. `Chapter.original_text`와
`Paragraph.original_text`는 각각 담당하는 원문 범위를 보존한다.

## TXT 가져오기 형식

- TXT 파일 하나를 책 하나로 가져온다.
- 파일명에서 확장자를 제외한 값을 책과 최초 장의 제목으로 사용한다.
- 최초 버전에서는 책마다 장 하나를 생성한다. 빈 파일도 빈 장 하나를 가진다.
- 하나 이상의 빈 줄로 구분된 블록을 문단으로 만든다. 문단 구분자는 콘텐츠 문단에 포함하지
  않지만 파일 전체 원문에는 그대로 남는다.
- 문장은 `.`, `?`, `!`, `。`, `？`, `！` 뒤의 공백 경계에서만 보수적으로 분리한다.
  쉼표와 세미콜론에서는 분리하지 않는다.
- 문장 조각 사이의 공백과 줄바꿈은 어느 한 문장에 그대로 남으므로, 문장들을 이어 붙이면
  `Paragraph.original_text`를 정확히 복원할 수 있다.
- 기본 문자 인코딩은 UTF-8이며 필요하면 호출자가 다른 인코딩을 명시할 수 있다.
- 파일은 universal-newline 변환 없이 읽으므로 CRLF도 `Book.original_text`에 보존된다.

## 가져오기 원칙

- 입력 텍스트의 유니코드 문자, 문장 부호, 공백 및 줄바꿈을 가능한 한 보존한다.
- 책과 장 정보는 사용자가 확인하고 편집할 수 있어야 한다.
- 가져오기 또는 원문 편집 때문에 기존 학습 이력을 자동 삭제하지 않는다.
- 형식 검증 오류는 원본 데이터를 변경하지 않고 사용자에게 명확히 알린다.

## 로컬 저장 범위

SQLite 저장소는 향후 책, 장, 문단, 문장, 사용자 작성 퀴즈, 학습 세션, 문장 시도, 이벤트 시도,
퀴즈 시도 및 복습 통계를 저장할 수 있어야 한다. 스키마 버전과 마이그레이션은 명시적으로
관리한다.

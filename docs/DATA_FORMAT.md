# 데이터 형식

## 목적

이 문서는 향후 텍스트 가져오기와 로컬 저장 형식이 지켜야 할 경계를 정의한다. 실제 가져오기
형식과 SQLite 스키마는 아직 구현하지 않았다.

## 콘텐츠 계층

콘텐츠의 논리 구조는 다음과 같다.

```text
Book
└── Chapter
    └── Paragraph
        └── Sentence
```

각 엔터티는 목록 위치와 무관한 안정적인 ID, 부모 ID, 원문 내 순서를 가져야 한다. 문장에는
정본인 `original_text`를 저장한다. 이벤트용 `display_text`나 사용자의 `typed_text`로 이를
덮어쓰지 않는다.

## 가져오기 원칙

- 입력 텍스트의 유니코드 문자, 문장 부호, 공백 및 줄바꿈을 가능한 한 보존한다.
- 책과 장 정보는 사용자가 확인하고 편집할 수 있어야 한다.
- 가져오기 또는 원문 편집 때문에 기존 학습 이력을 자동 삭제하지 않는다.
- 형식 검증 오류는 원본 데이터를 변경하지 않고 사용자에게 명확히 알린다.

## 로컬 저장 범위

SQLite 저장소는 향후 책, 장, 문단, 문장, 사용자 작성 퀴즈, 학습 세션, 문장 시도, 이벤트 시도,
퀴즈 시도 및 복습 통계를 저장할 수 있어야 한다. 스키마 버전과 마이그레이션은 명시적으로
관리한다.
